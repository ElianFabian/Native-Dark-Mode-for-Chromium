# Rendering lab

The lab is developer tooling, separate from the shipped extension. It implements the first capture/analyze/compare workflow from [the plan](DIAGNOSTICS-AND-REGRESSION-PLAN.md). It is not the complete regression gallery or an accessibility certification.

## One-command interface

From the repository root, with Node.js/npm installed:

```sh
npm run lab
```

Open **http://127.0.0.1:8787**. Click **Run local smoke suite**. The server starts an isolated installed Brave/Chromium, captures the specimens with the actual unpacked extension, closes that browser, and makes the reports available in the page. No Python or `npm install` is needed for the lab. On Windows PowerShell use `npm.cmd` if execution policy blocks `npm`.

Discovery currently covers Brave's usual Windows/macOS locations and Chromium's Linux locations. Set `CHROMIUM_PATH` to another supported executable if needed. Only Brave/Chromium on Windows has been checked. A browser that refuses `--load-extension` produces an explicit startup error; the lab does not attach to a personal browser profile. `LAB_PORT` overrides port 8787. Stop the server with Ctrl+C; an in-progress owned capture is canceled and its profile cleanup is attempted.

The interface has three views:

- **Cases:** original previews and full-size specimen links, with automated/capture-only/manual status. Compact previews have their own presentation; measurements use the canonical page at fixed viewport dimensions. The coverage inventory lists every rendering-guide symptom and its partial/pending status.
- **Inspect report:** open a saved run or a capture JSON. Filter by theme, status, category, maximum numeric value and case/element. Select a measurement to inspect original/applied swatches, screenshots, element bounds, generated layers and raw facts. Screenshots load automatically for reports generated by the local server; independently imported JSON does not load arbitrary image paths.
- **Compare runs:** select two capture JSON files. Both are re-analyzed with the same policy. The result identifies resolved/regressed/improved/worsened/changed/new/missing findings, as applicable. Environment changes and changed node structures are marked not comparable. Live structural locators remain best-effort and are not treated as verified cross-run identities.

Live website text is omitted by default. `--labels` explicitly opts into bounded visible text/accessible labels for locating public-page findings; input values and cookies are never exported. Local fixtures include their synthetic labels automatically. Raw background/mask/resource filter URLs are omitted; source and effective paint evidence are kept. Public/live captures make normal website requests but omit screenshots by default. Local fixture screenshots are deliberately included. Reports stay under the ignored `research-artifacts/diagnostics/run-*` directories. Review any report before sharing it.

## Automatic review queue

The viewer opens a source-aware queue before the raw measurements. `triage.mjs` is a deterministic pure layer over captured facts; it makes no AI or network calls. It groups the four sides of one border and repeated themes/levels while retaining every check ID. It does not merge different elements, states or scales.

- **High:** changed geometry/width or newly exposed transparent border. Still a candidate: reflow can be intentional and live identity is best-effort.
- **Candidate:** authored paint passed the numeric reference and themed paint did not, or already-low measured contrast worsened by more than 0.25. Unsettled paint needs a new capture first.
- **Advisory:** a threshold-only observation without measured degradation, uncertain source identity, or stronger Off border contrast without changed width. This is not automatically a defect.

Unsupported paint remains counted as unknown and inspectable in raw measurements. The default queue shows priority candidates; choose **All open findings** for advisories. Fixture assertion failures are counted separately and are not overridden by accepting an appearance. Location includes CSS-pixel coordinates, tag/landmark, exact locator, and optional captured label. Labels identify a captured moment, not a guaranteed stable live-page selector.

**Accept this appearance** retains the raw values/status and stores a separate local review decision. **Reopen review** reverses it. Decisions can be exported/imported as JSON. They use a compact, non-security fingerprint scoped to the report and exact measured paint; changed facts or a fresh run reopen review. Old reports without run IDs are scoped by their complete captured content. No site-specific acceptance or contrast policy is added to the renderer.

On the eight saved public audits from November 11, re-analysis/grouping plus summary writes took approximately 0.20 seconds on the development machine: 5,244 raw measurements, 99 themed review rows, 21 groups, one priority candidate and 20 advisories. This excludes browser capture, JSON loading and AI interpretation; it is an observation, not a latency guarantee. BOOTH's four colored tiles remain advisories because their low numeric ratios did not degrade from the authored paint, consistent with the user's visual acceptance.

## Extended visual gallery

Use the case search or **Capture extended gallery**. Six generic groups reconstruct reported icon, image, control, border, surface and interaction mechanisms. Five site groups add original Gradle, Indeed, SEPE, Junta, InfoJobs, school/funding and formacion.cc assets and selected structures. There are local PNG/SVG silhouettes, mixed wordmarks, real static and animated GIFs with transparent/multicolor/opaque negatives, sprites, clipped/nested SVG, generated arrows, select arrows, placeholders, deal labels, matching-fill chips, fractional/transparent borders, shadow cards, tabs, dividers, image-backed text, hover/sticky/carousel/dot examples. The gallery uses two columns on wide layouts, one below 900px, and taller previews (420–720px based on viewport height).

The extended capture matrix produces 77 steady-state snapshots (11 groups × original plus three themes at Off/Maximum). Its one runner assertion is the pipeline's deliberate border fault self-test, not a claim that all specimen paint passed. The separate UI check asserts a narrow Indeed reproduction: embedded gradient identity, six original SVG path sets and modeled heading contrast at the two gradient endpoints in all custom themes. Other image pixels, animation performance, native menus and complex SVG backing still need visual/targeted analysis. See [specimen provenance and expectations](../fixtures/diagnostics/README.md). Synthetic assets and 22 original/decoded public resources are checked in; original-site scripts and private account content are excluded. Resource source URLs, extraction methods and pinned checksums are recorded separately. Local use requires no public-site network requests.

The UI labels capture-only groups **Measured · review required**: supported computed measurements are analyzed automatically, but the group lacks complete fixture-specific assertions. **Partially checked** identifies narrower automated expectations, including Indeed/Junta source fidelity, the reported school logo/GIF context, and selected generic glyph, artwork, surface and card cases. Successful capture counts alone do not establish correct paint.

The separate shared rendering check covers 24 theme/case combinations. It independently samples the displayed sprite/background ink, checks equivalent glyphs and repeated resampling, retains multicolor pixels and animated frames, checks captioned artwork backings, models gradient endpoints and checks sampled picture labels without rectangular backings, and checks short-card emphasis/shadows and article/page separation without geometry changes. Compact neutral contact glyphs target at least 10:1 in these local checks; labeled blue/orange inks target 4.5:1 while retaining their color families, and repeated labeled tiles retain their geometry. Unlabeled patterns and illustrations remain preservation controls. All six border levels, single-glyph controls, equivalent light-source cards and 24-frame steady-backing and 32-frame changed-backing SVG probes are checked in each theme. This targeted pixel/model evidence supplements the general analyzer; it does not make arbitrary image pixels supported by that analyzer.

The inventory now maps 42 mechanisms partially and leaves two pending; a mapping is not an automated pass. Scroll-banner and prior CORS/Shadow DOM fixtures remain linked, with lifecycle/performance automation pending.

## Verification from a single command

```sh
npm run verify -- --quick --browser
```

Runs syntax checks, Node tests, the local steady-state rendering smoke suite, lab UI/asset checks and the shared rendering checks above. It starts/stops its own fixture servers and browsers; no manual startup sequence is required. UI checks include queue acceptance/reopening, narrow large-text layout, keyboard focus, server request guards, decoding synthetic/original local assets, visibly changing GIF frames and the narrow source-fidelity assertions. Omit `--quick` to include launcher artifact tests, which additionally need Python 3 and the platform prerequisites described in the README. The ordinary `npm run verify` still does not run browser checks unless `--browser` is requested.

The smoke matrix is four canonical specimens, the original plus all three custom themes, Off/Maximum and CSS zoom 1.25 with DPR 1. That is 28 captures. Three specimens have automated assertions (18 theme/level combinations); the fourth is capture-only. A deliberately corrupted DOM border must also be detected, giving 19 assertions. Assertions require measured evidence, preserve dimensions/path data and relevant negatives, and reject unsettled captures. A report containing only unsupported measurements does not satisfy a required fixture assertion.

Pure Node tests cover contrast/compositing reference vectors, determinism, unsupported backings, actual SVG ink and a known constant-white filter, fractional widths, exposed transparency, comparison drift, malformed reports, and inventory completeness. They do not import renderer eligibility decisions as their oracle.

## CLI and offline analysis

```sh
npm run diagnose
npm run diagnose -- --full
npm run diagnose -- --gallery
npm run diagnose -- --url https://example.com --selector "main" --themes chromium --levels off --scales 1.25
npm run diagnose -- --url https://example.com --labels
npm run diagnose -- --analyze capture.json --output analysis.json
npm run diagnose -- --analyze capture.json --summary --output summary.md
npm run diagnose -- --before before.json --after after.json --output comparison.json
```

`--full` expands the selected specimens to six border levels and zoom 1/1.25/1.5; it does not add interaction-state coverage. `--scales`, `--themes`, `--levels`, `--browser` and `--output-directory` customize a run. CSS zoom and DPR are recorded separately; this is not a claim to reproduce every OS/browser zoom combination. `audit:website` and `scripts/dev/audit-website.mjs` now enter the same pipeline, replacing the old duplicated collector/analyzer. Use `--help` for accepted flags. Captures write `capture.json`, `analysis.json`, `triage.json` and a readable `summary.md`, not the old `audit.json` schema. The fixture hash includes HTML, CSS, JavaScript and local artwork to flag cross-run drift.

Capture JSON contains the environment, a renderer hash, a fixture hash, source/themed snapshots, coverage and stability information, screenshot filenames and assertion results. Analysis is a pure function of captured facts. Volatile directory names/timings do not enter check identity. Local cases use permanent fixture IDs. A fresh owned tab/document is replayed before each steady-state theme/level capture; removing a single element marker is not used as an authored baseline.

Before capture, fonts and visible images are awaited with a two-second bound per readiness group; targeted paint must remain identical for 200ms, within a six-second bound. That is observable stability, not proof that arbitrary delayed website scripts have finished. A timeout is reported as unstable. Collection is capped at 1,500 visible records and 10,000 visited elements, uses per-snapshot style/backdrop caches, includes open roots, and reports frame/closed-root gaps. Reports do not quietly convert missing coverage to a pass.

## Current measurement scope

- Known opaque/composited CSS backings, text fill versus color, font context and placeholders.
- All four border sides, authored and generated layers, widths, shadows, outlines, inside/outside contrast when known. Decorative borders have no universal minimum; source-to-theme amplification and geometric changes are separate signals.
- Simple inline SVG paint, excluding definitions. The exact CSS chain `brightness(0) invert(1)` is modeled as white ink with preserved alpha; unrelated filters remain unsupported. Raw fill and effective ink are both inspectable.
- Source-to-theme layout deltas and cross-run comparison with environment/fixture drift guards.

Artwork pixels, nested SVG backings, overlapping surfaces, native menu popup pixels and more complex compositing remain unsupported or manual. The existing static/dynamic fixtures are linked, but automated hover, scroll, frame/Shadow DOM lifecycle assertions, performance tracing and perceptual text metrics are later steps. Do not interpret the first slice's 19 passing assertions as coverage of every previously fixed website issue.

## Adding a case

1. Add a minimal generic reproduction with its relevant CSS, generated layers and local resources. Give measured nodes stable `data-audit-id` values.
2. Register the specimen/status/evidence in [cases.mjs](../tools/diagnostics/cases.mjs), and map the rendering-guide mechanism in [coverage.json](../tools/diagnostics/coverage.json). Unresolved cases stay pending or capture-only.
3. Add positive and negative expectations to the runner only when the measurement is supported. Preserve the case after fixing it.
4. Run the unified browser verification and inspect the resulting evidence. Update the fix inventory with local versus live confirmation.

The inventory-completeness Node test fails if a rendering-guide symptom has no corresponding inventory entry. This protects the workflow without claiming that an inventory entry itself is a test.

See the [eight-page public audit](LIVE-PAGE-AUDIT-2026-11-11.md) for actual results and tool limitations discovered on previously reported sites.


The November follow-up also records native-engine versus custom screenshots for the generic icons, borders and surface groups under the same viewport. These owned CDP references are visual evidence, not new default pass thresholds. Public SEPE verification sampled four category icons over 90 scroll frames in each custom theme: one constant filter per icon was observed, no untinted frame was observed and the four final card surfaces matched. The trace alternates between scroll positions 0 and 400 CSS pixels. The portable state probe deliberately changes an authored backing, so an appropriate filter-strength change is allowed; dropping to the unadapted filter is a failure. The settled sibling surfaces must match.

The source-element HTML had 24 double-encoded UTF-8 sequences even though the server already declared UTF-8 correctly. They are repaired in the file; Node and served-browser checks retain Spanish labels and reject mojibake. Do not blindly transcode mixed files or change already-correct asset bytes.

A follow-up trace also caught an incomplete authored-style cache: child-only projection did not retain the parent card's display/shadow/border context. That changed the computed backing while the visible backing stayed constant. The shared renderer now retains that classification context. The steady-backing probe rejects any filter-color change during class resampling/scroll; the changed-backing probe permits appropriate adaptation without dropping the verified filter. Raw traces remain separate from automated pass counts.


Flow-image text regression: the manufactured four-direction halo also outlined the underline and made text look doubled. The shared renderer now selects foreground only, preserving authored text shadow/decoration/stroke and layout. The surface specimen includes both plain source text and an authored soft-shadow control, with unchanged computed styling/geometry asserted in all three custom themes. Mixed image regions can still miss a numeric contrast target; removing the artificial stroke is not reported as a contrast-threshold pass.


The image-text follow-up uses weighted word-region sampling and the shared perceptual candidate policy documented in [Text over images](IMAGE-TEXT-CONTRAST.md). The colorful source specimen itself has weak text, so source preservation is not treated as a readability pass. Bright/dark picture controls exercise opposite ink choices; all three custom themes retain source shadows/decoration and stable ink over 24 resampling frames. Internal uncertainty and candidate statistics do not currently add a new UI badge; picture rows remain partially checked, and visual/spatial masking review remains necessary. The report renderer hash now covers the color primitive, image-text policy and renderer together.
